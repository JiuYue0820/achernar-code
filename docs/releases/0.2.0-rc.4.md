# Achernar Code 0.2.0-rc.4 — reliability candidate

- Runtime settings: `/settings` and `achernar settings` save validated retry counts, backoff bounds, provider request deadlines, command/task deadlines, automatic diagnostics and file-read caching. Desktop uses the same setting schema with its own saved configuration.
- Retry transient connection failures and HTTP 408/429/500/502/503/504 with bounded exponential backoff and jitter. Respect Retry-After; if the server asks for a longer wait than configured, return that delay instead of retrying prematurely. Never replay a response after streaming begins. Cancellation interrupts backoff.
- Commands default to 10 minutes; explicit overrides accept up to 1 hour and remain bounded by the task deadline. Tasks default to 30 minutes and accept up to 4 hours.
- Literal or regex search, include/exclude globs, case-sensitive matching and result limits are available to the agent and the `search` command. Regex work runs in a cancellable worker with a one-second deadline. Matching works on the desktop's embedded Node runtime.
- File write/edit approvals show a scrollable unified diff. PgUp/PgDn and the mouse wheel scroll the CLI preview. Approval cannot overwrite a file that changed after its preview. Replacement strings preserve literal dollar sequences.
- Automatic per-file validation follows writes/edits and is included in the next model request. CLI uses its bundled JS/TS LSP; desktop uses a bounded TypeScript compiler worker. JSON is parsed locally. Disabled, unsupported and unavailable diagnostics are explicitly reported and are not treated as successful validation.
- Repeated reads of unchanged bytes/ranges return a revision reference; `fresh:true` forces text after compaction. The cache is scoped to one running toolset, not persistent disk caching.
- Compaction retains the full current user request, tool-call/result pairing and explicit denials. Summary failure falls back to progressively shortened historical output.
- Tests include real local HTTP fault injection, real JS/TS validation, Electron persistence and approval checks, and an independently installed npm package. These are deterministic engineering checks using `runtime-fixture` / `package-fixture`, not a new real-model quality benchmark.

The additional CLI upgrade includes native Git operations, per-task cost reservations/caps, pre-output model failover, restricted file write roots, user tool hooks, task undo/redo, redacted session export, system-following TUI language and fixed fixture/live eval commands. Completed old tool exchanges can be retired during compaction without orphaning results. JSON system fields stay English.

Follow-up integration fixes cover hooks for mode/workspace/delegation controls, per-attempt retry cost accounting, eval configuration checks before tasks run, endpoint-bound saved credentials, and preservation of observed usage in failed eval reports.

The terminal workbench adds Ctrl+P command search, grouped settings, local source/search/Git/diff viewers, multiline file/stdin task input and draft preservation across dialogs. Windows Job mode adds process-count/memory limits with child cleanup while retaining host MCP/LSP. It does not restrict filesystem or network access.

The five-task eval now accepts explicit model matrices. Default-branch CI uses a live matrix gate that fails on missing configuration. Two `agnes-3.0-flash` / `agnes-2.5-flash` matrices each passed 2/10, predominantly limited by HTTP 429. A separate `agnes-2.5-flash` typed-edit rerun passed after `oldText/newText` compatibility was fixed; full failed reports remain published with that focused result.

These features have explicit limits: restricted mode is not OS isolation; invoices can differ from estimated budgets; snapshots cannot undo out-of-project side effects; untranslated technical labels use English. See `docs/RELIABILITY.md` and `docs/EVALUATION.md`.

This remains an unpublished candidate. No package upload, Git push or remote CI success is implied by local verification.
